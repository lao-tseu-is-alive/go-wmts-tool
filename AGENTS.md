# AGENTS.md

Guidance for coding agents working on go-wmts-tool.

## What it is

- `cmd/saveWmtsTiles`: CLI that pre-generates WMTS png tiles (Swiss grid LV95, EPSG:2056) from a WMS server,
  by requesting meta-tiles (default 4x4) and splitting them. Main user: operators running it with `sudo`
  on the cartotest servers, typically `-workers 2 -zoom <n> -layer <layer>`. Options are documented in `README.md`.
- `cmd/server`: WMTS proxy server serving the cached tiles and fetching missing ones on the fly,
  with a Vue front in `cmd/server/wmtsProxyFront` (embedded from its `dist/`).

## Commands

```bash
go build ./...
go vet ./...
go test ./...            # add -race when touching the worker pool
```

Go version is pinned to 1.24.3 (`go.mod` and `.github/workflows/release.yml`): do not use newer APIs
such as `sync.WaitGroup.Go` (1.25).

## Layout

- `pkg/wmts`: grid math (`grid.go`, `lausanne.go`), layer config (`layers.go`, `config.go`), tile paths (`filePath.go`).
- `pkg/tools`: HTTP client, `FetchImageWithRetry` (single place for WMS retry logic), atomic file writes (`WriteFileAtomic`, `SavePng`).
- `pkg/config`: environment variables (`LOG_LEVEL`, `LOG_FILE`, `BUFFER_SIZE`, `PORT`, ...).
- `pkg/golog`: logger interface used everywhere (`l.Info`, `l.Warn`, ...). Default level is warn, so `Info` is hidden for users.

## Conventions and pitfalls

- Reuse the existing helpers: `lc.TileImgPath(...)` for tile paths, `tools.FetchImageWithRetry` for WMS requests,
  `tools.SavePng` / `tools.WriteFileAtomic` to write tiles (temp file + rename, mode 0644 so the web server can read them).
- `wmts.Grid` is immutable after creation: no mutex needed.
- In `main.go`, dereference flag pointers only after `flag.Parse()` (this bug silently ignored `-metatile` and `-buffer` before v0.6.0).
- Validate every new CLI flag in `main.go` with an explicit `l.Fatal` message.
- `saveWmtsTiles` must exit with status 1 when tiles are missing: operators and scripts rely on it.
- Never edit `cmd/server/wmtsProxyFront/dist/`: it is generated by the front build.
- `config.yaml` often holds the maintainer's local, uncommitted layer changes: do not commit it unless asked.

## Release

- Bump `VERSION` in `pkg/version/version.go`, commit, then run `scripts/tag_new_release_github.sh`
  (it refuses to tag a dirty working tree). Pushing the `vX.Y.Z` tag triggers the GitHub workflow
  that builds the binaries for all platforms. No need to build releases locally.

## Testing against a WMS server

No real WMS server is reachable from a dev machine. For end-to-end checks, run the built binary against a small
local fake WMS (an `http.HandleFunc` returning a png of the requested `WIDTH`x`HEIGHT`, with injected 502s)
and a config whose `wms_backend_url` points to it and whose `caches.local.folder` is a temporary directory.
